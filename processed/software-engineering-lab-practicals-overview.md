# Software Engineering Lab Practicals Overview

> This document outlines the eleven practical experiments defined in the B.Tech Computer Science and Engineering curriculum for Software Engineering. The lab coursework guides students through the complete software development life cycle using an Attendance Management System case study, covering requirements engineering, SDLC model selection, project management planning, cost estimation via COCOMO, structured and object-oriented modeling, coding standards, test case design, automated testing tools, and quality assurance.

## Lab Practicals Index

The following table lists all 11 practical experiments extracted from the Software Engineering lab manual:

| Practical No. | Experiment Title | Core Focus & Methodology |
| :--- | :--- | :--- |
| **01** | Project definition and objective of the specified module and perform Requirement Engineering Process | Defining scope, user roles (Admin, Teacher, Student), and functional features for an Attendance Management System. |
| **02** | Identify Suitable Design and Implementation model from different software Engineering models | Comparison of SDLC models (Waterfall, Incremental, Prototyping) and justification for choosing the Spiral Model. |
| **03** | Prepare a Software Requirement Specification (SRS) for the selected module | Documentation of functional requirements, software quality attributes, hardware/software interfaces, and protocols. |
| **04** | Develop a Software Project Management Plan (SPMP) for the specific module | Scheduling principles, PERT, CPM, milestones, work breakdown, and Gantt chart construction. |
| **05** | Do Cost Estimation using Different Software Cost Estimation Models | Software estimation using Function Point analysis and the Basic COCOMO model for organic software. |
| **06** | Prepare System Analysis and System Design of identified requirement specification using structured design | Creating Data Flow Diagrams (Level 1 and Level 2 DFDs), Data Dictionaries, and Structure Charts. |
| **07** | Designing the module using Object-Oriented approach | Constructing UML diagrams: Use Case Diagrams, Class Diagrams, State Diagrams, and Sequence Diagrams. |
| **08** | Defining Coding Standards and walkthrough | Establishing coding conventions, naming rules, code review techniques (Pair Programming, Over-the-shoulder, Meeting-based, Tool-based). |
| **09** | Write the test cases for the identified module | Formulating test plans, defining inputs, conditions, expected results, and tracking pass/fail statuses. |
| **10** | Demonstrate the use of different Testing Tools with comparison | Evaluating automated tools (Selenium IDE, TestComplete, Katalon Studio, UFT, Watir) and setting up Selenium with ChromeDriver. |
| **11** | Define security and quality aspects of the identified module | Analyzing software quality factors (Portability, Usability, Maintainability, Reliability, Efficiency) and Software Quality Management Systems (SQMS). |

## Key Lab Highlights

* **Case Study Module:** Attendance Management System, focusing on role-based access for administrators, teachers, and students.
* **Design Approaches:** Dual exposure to both Structured Design (DFD Level 1 and 2) and Object-Oriented Modeling (UML suite).
* **Project Management & Estimation:** Integration of Basic COCOMO formulas ($Effort = a_1 \times (KLOC)^{a_2}$, $T_{dev} = b_1 \times (Effort)^{b_2}$) alongside Function Point analysis and critical path scheduling.
